## B-Q24 — [B] New passwords: keep hashing them with SHA-512, or move to yescrypt as Ubuntu, Debian and Fedora have? — Status: OPEN (raised 2026-10-07)

**In short:** SlateOS never stores a password itself. It stores a scrambled
form of it (a *hash*) that can check a typed password but cannot be turned
back into one. If someone steals the account file, they can still try
guesses against those hashes on their own hardware, as fast as it allows.
How fast depends on the scrambling method. Ours is SHA-512, which a
graphics card can try billions of times a second. Ubuntu, Debian and Fedora
switched new passwords to *yescrypt*, a method built to be slow and to need
a lot of memory for every guess, which makes stolen hashes far harder to
crack. Which should SlateOS use for passwords set from now on?

**What it is not about:** passwords already set keep working either way.
Every account keeps its own method until its password is next changed.
Since 2026-10-06 SlateOS can check yescrypt passwords (lane D), so accounts
brought from an Ubuntu machine already work. This is only about the method
a *new* password gets: `passwd`, `useradd`, `chpasswd` with no `-c`, and
the account tools in the desktop.

| Option | *What changes* | For | Against |
|---|---|---|---|
| **A. yescrypt** *(recommended)* | a new password is stored as `$y$j9T$...` instead of `$6$...`; checking one takes about 16 ms instead of 2.5 ms, and 16 MiB of memory for that moment | the method current Linux distributions chose; a stolen account file costs an attacker far more per guess, especially on graphics cards, which have little memory per core | each login check costs a little more time and memory (unnoticeable to a person, but a server checking many passwords at once feels it); a password file copied to a very old Linux system could not be checked there |
| B. Keep SHA-512 | nothing | works everywhere, including very old systems; cheapest per check | a stolen account file is much cheaper to attack than on a current Ubuntu machine |

**Words used above:**
- *hash*: the scrambled, one-way form of a password.
- *SHA-512 crypt*: the method marked `$6$`, the default from about 2008 to
  2021.
- *yescrypt*: the method marked `$y$`, the current default of Ubuntu
  (since 22.04), Debian (since 11) and Fedora (since 35).
- *memory-hard*: needing a lot of memory for each guess, which is what
  makes guessing in bulk expensive.

**If it is never answered:** new passwords stay SHA-512 (option B), which
is safe and works. Nothing is blocked. The only cost is that SlateOS's
password files stay cheaper to attack than those of the systems people
compare it with.

**Where it would change:** `userspace/userdb` (`PASSWORD_METHOD`, and the
salt each new password gets, which would come from `crypt_gensalt` as
`chpasswd`'s do: a yescrypt salt has rules a SHA-512 one does not) and the
tests that pin a `$6$` entry. `authlib`'s timing cover for "no such user"
already follows whatever the accounts use (design-decisions §1061).
