# The counted `guessed-value` backlog for scripts/check-option-refusal.py.
#
# Each line is `<enclosing function> <count>`: that many places inside that
# function read a word the user typed, fail to parse it, and substitute a
# default -- design-decisions.md §600's second prohibited shape. They are
# recorded rather than exempted, so that:
#
#   * the number is visible and can only go down;
#   * a NEW site in a function not listed here, or one site too many in a
#     function that is, fails the check immediately;
#   * an entry claiming MORE sites than exist is itself reported, because
#     that means the site was fixed (lower the count) or the function was
#     renamed (the entry now exempts something it was never meant to).
#
# Keyed by function, never by line number: line numbers drift on every edit,
# and an allowlist that rots is a rubber stamp.
#
# Do not add a function here to buy silence for new code. The only legitimate
# edits are downward, and deleting a line entirely is the goal.
#
# Burn-down is tracked in known-issues.md as
# `A-KSHELL-A-HUNDRED-AND-NINETEEN-FUNCTIONS-GUESS-A-VALUE-FOR-A-WORD-THEY-COULD-NOT-READ`.
# That name is now an undercount, and is kept only because renaming a
# known-issues key breaks every reference to it. The entry was written when
# this checker matched its regex against a *line*, which found 240 sites in
# 110 functions. Matching against a *statement* instead -- the chain is the
# same code either way; `cargo fmt` merely decides whether it fits on one
# line -- found 466 more, for 706 across 240 functions. Nothing was added to
# the shell to cause that jump and nothing regressed: the gate simply began
# seeing what had been there all along. See
# `A-KSHELL-THE-OPTION-GATE-COUNTS-ONE-LINE-AND-RUSTFMT-USES-FOUR`.
#
# It happened a second time, on 2026-08-29. The detector required a literal
# `.parse()`, so the base-16 spelling of the same defect --
# `u16::from_str_radix(v, 16).unwrap_or(0)` -- was invisible, hiding 19 sites
# across 8 functions, four of which appeared nowhere below because they were
# never seen rather than deliberately exempted. Both under-counts were found
# by looking at a *function* that ought to be listed here and noticing it was
# absent; neither was visible in the total, which looked healthy throughout.
#
# So: this number is a floor, not a measurement. A count that has been wrong
# twice, both times for reasons unrelated to the code it inspects, should be
# audited the same way both times -- name a function you believe is dirty and
# check that the gate agrees. Reading the total proves nothing. See
# design-decisions.md §634, which is also why that detector fix and the 30
# sites it exposed landed in one commit rather than two.
