## C-Q33 — [C] Nothing starts a program when you sign in. Where should the list of programs to start live, and in what form? — Status: OPEN (raised 2026-10-05)

**In short:** you cannot have a program open by itself when you sign in --
a chat program, a sync tool. Three half-built "startup apps" screens record
such a list and nothing obeys any of them
(`known-issues.md` `TD-C-THREE-STARTUP-MANAGERS-AND-NOTHING-THAT-STARTS-ANYTHING`).
`design.txt` asks for "only one or two ways to load programs on startup, not
5 or 6", and the roadmap puts the list inside the service manager (the part
of the system that starts background services when the machine boots). But
that runs before anyone signs in, so it cannot start *your* programs, in
*your* desktop, when *you* sign in. Before lane C builds the part that
starts them, the question is where the one list lives.

**Two terms.** *Autostart folder*: what every Linux desktop reads -- one
small file per program in `~/.config/autostart` (yours) or
`/etc/xdg/autostart` (installed programs'); a program ported from Linux
often installs one. *Ready*: the program has finished starting (for a
windowed program, its window is up).

| Option | *What changes* |
|---|---|
| **A. One list per user, SlateOS's own, started by the desktop when you sign in** (recommended) | a `startup.yaml` in your settings, in order, each line a program and its arguments, "wait until it is ready before the next" where the roadmap asks for it; Settings shows it as a list you reorder and switch. A ported program's autostart file is offered there, switched off until you turn it on |
| **B. The autostart folders are the list, started by the desktop** | ported programs start at sign-in as on Linux, with nothing to turn on; no order and no waiting (that format has neither); Settings shows the folders' files with switches |
| **C. The service manager's list learns about users and starts them at sign-in** | one mechanism with the services, as the roadmap words it; the boot-time code (lanes A and B) must learn when someone signs in and start programs inside their desktop; the desktop only says "signed in" |

**For A:** it is the model the roadmap describes -- ordered, wait-for-ready,
one list you can find in Settings -- and it is the one the capability rules
fit: the roadmap's `startup.autostart_self` ("start me when I sign in") is a
grant to add *one* entry to *one* list, which a folder anyone installing a
program can drop files into does not allow. **Against A:** a program ported
from Linux does not start by itself until you switch it on.

**For B:** compatibility for free; GNOME and KDE work this way. **Against
B:** an installed program can make itself start at every sign-in without
asking, which is the Windows problem `design.txt` names; and no order or
waiting.

**For C:** literally one mechanism. **Against C:** the most work, across
two other lanes, for the part a user sees least; and a program that needs
your desktop is started by something outside it.

**Under any of them** the three existing screens go: the desktop's own
(`gui/desktop/src/startup_settings.rs`, never shown) is deleted -- done
2026-10-06, as it holds whichever is chosen -- and lane E's
`apps/startupmanager` and the Settings page become the list's editor.

**If it is never answered:** nothing gets worse -- nothing starts at sign-in
today. Every day it waits is a day the switches in those screens do nothing.
