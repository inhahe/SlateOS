# rootfs-bin-manifest.txt -- the SlateOS-native programs the image must carry.
#
# Read by scripts/create-ext4-rootfs.sh. One binary name per line; blank lines
# and #-comments ignored. These are staged first, and are the ones the boot
# tests and the image's build chain rely on.
#
# SINCE 2026-10-01 THIS IS NOT ALL THAT SHIPS. Every program the workspace
# builds goes on the image (design-decisions §1053, the operator's answer to
# B-Q21; §1164, how): after these, the recipe stages every other program
# `scripts/build-userland.py --list` reports, except what
# scripts/rootfs-bin-kept-off.txt keeps off, each there with its reason. A
# name here says more than "it ships": that the image is not the image
# without it.
#
# WHY A LIST FROM THE WORKSPACE AND NOT A SCAN OF target/x86_64-slateos/release/.
# The first version of the staging block did scan that directory, and the
# coupling it created is a defect: `cargo build` inside a crate directory
# changed what the operating system image contains. That is not hypothetical.
# On 2026-09-13 a measurement build of all 193 userspace crates -- run purely to
# find out whether they cross-compile, which all 276 binaries do -- turned the
# next image build into
#
#     [rootfs] staged 260 SlateOS-native utilities from userspace/ into /bin (204 MiB)
#     mke2fs: Could not allocate block in ext2 filesystem while populating file system
#     *** rootfs.ext4 was NOT written ***
#
# A developer debugging one crate must not be able to change, or break, the
# image that way. The image now sizes itself from what it stages, and what it
# stages is this list and the workspace's programs -- never what is lying in
# the build directory.
#
# THE NAMES THAT ARE NOT HERE, and are not on the image either -- the fourteen
# promoted fastpy commands own (design-decisions §108 part 1), and sh, which is
# dash -- are in rootfs-bin-kept-off.txt now, with their reasons. The staging
# block also refuses to overwrite a name already staged, so that list and that
# guard have to BOTH be wrong before a swap can happen silently.
#
# ON awk AND ar, ADDED 2026-09-13. The image already carries a build chain --
# /bin/make, /bin/cmake, /bin/tcc, /bin/bash, /bin/python3 -- and these are the
# two pieces of it that were missing:
#
#   awk   an autoconf `configure` script is mostly sh, sed and awk. sed and the
#         rest of that set are here via coreutils, and awk was not, so a
#         configure run would die on the one tool nobody lists.
#   ar    building a static library is `ar rcs`. A toolchain that can compile
#         and link but cannot make an archive cannot build most C projects.
#
# awk is a coreutils binary, missing by accident: this list was generated with
# `ls src/bin/*.rs`, and cargo also accepts the directory form
# `src/bin/<name>/main.rs`, which that glob cannot see.

ar
awk
logrotate

# ALIASES. A line `name = producer` creates `name` as a second name for a
# binary on the image -- one listed here, or one of every other program the
# workspace builds, which the recipe stages before it makes these. Multi-call
# programs read argv[0] -- our `ar` is `ranlib` and `strip` when invoked
# under those names -- and that only works if something creates the name.
# `scripts/multicall-aliases.py` found 167 such names across the tree that
# nothing produced. `ranlib` in particular is not optional: an autoconf
# build calls it straight after `ar`.
