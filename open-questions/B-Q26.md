## B-Q26 — [B] Process Lasso's controls: is what is planned enough, or add three more? — Status: OPEN (raised 2026-10-09, answering your question in `open-questions/answers.2.txt`)

**In short:** you asked whether SlateOS should have controls like Process
Lasso's (a Windows tool that remembers a priority for each program, holds back
programs that hog the processor, and so on), or whether what is planned will be
enough. Most of it is planned already -- the table below. Three of Process
Lasso's controls are not, and this asks whether to add them to the list.
Nothing is built either way yet; the answer only decides what goes on the list.

**Already planned** (`roadmap-detailed.md` §1.3, and `design.txt`):

| Process Lasso | SlateOS's plan |
|---|---|
| A priority remembered for each program (processor and disk) | "A default priority per program, remembered" -- your proposal of 2026-09-26: set in Settings or from the task manager ("always use this priority for this program"), applied however the program is started |
| ProBalance: lowers the priority of a program that hogs the processor, so the desktop stays responsive | The same aim, met earlier: a share of processor time, memory and disk speed is kept back for the desktop and the program in front, so a runaway program never gets all of it ("guaranteed resource headroom"). Process Lasso reacts after the slowdown; this prevents it |
| Performance mode, "gaming mode" | Workload profiles -- Desktop, Gaming (the program in front comes first), Development, Database -- chosen in Settings |
| Disk priority | Disk priority classes -- realtime for audio and video, normal levels, idle for indexing and backup -- per program, changeable while it runs |
| Limits on memory, disk, processor time | Limits set when a program starts and enforced by the kernel (`design.txt`: "set resource limits at process launch") |
| Changing a running program's priority, pausing it | Done |

**Not planned -- the three this asks about:**

1. **Remember which processors a program may use** ("CPU affinity": "this game
   uses cores 2 to 7"). On Intel's newer chips, which mix fast cores with slower
   power-saving ones, that includes "run this on the fast cores" or "keep this
   on the slow ones". Choosing processors for a program that is already running
   works today (`taskset`); remembering the choice does not.
2. **A cap on one program's processor use** -- "never more than 25%", or "no
   more than 2 cores" -- remembered like the priority.
3. **Switch profile while a program runs** -- Gaming while the game is open,
   back to Desktop when it closes.

Process Lasso also has things I would leave out: blocking programs from running
by rule (that is the permission system's job), restarting a program that exits
(the service manager does that for services), and trimming programs' memory in
the background ("SmartTrim", a Windows workaround that usually makes things
slower, not faster).

### The options

| Option | *What changes* |
|---|---|
| **A. Add all three** to the per-program settings already planned | Settings and the task manager offer, per program, which processors it may use, a cap on its processor use and a profile to switch to, beside its remembered priority |
| **B. Add 1 and 2 only** | As A, without the automatic profile switch; profiles are changed by hand |
| **C. Add nothing** | A program's remembered setting is its priority only; pinning a program to some cores means running `taskset` every time |

**My recommendation: A.** All three are stored, shown and applied in the same
place as the remembered priority, and the kernel already has what they need --
processor masks, limits and profiles -- so they cost settings screens, not new
machinery. Chips with two kinds of core are becoming the usual kind, and
Windows 11's task manager has an "efficiency mode" for the same reason.

**If this is never answered:** nothing is affected. The remembered priority
goes ahead as planned; these three are simply not on the list.

**Where it bites:** `roadmap-detailed.md` §1.3 (the per-program priority item
would grow); the Settings app (lane C), the task manager (lane E), and the
place every process is created (lane A's kernel).
