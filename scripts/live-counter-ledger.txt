# Reviewed sites for scripts/check-live-counter-reads.py.
#
# Each line is `<file>::<function>  <reason>`: an equality assertion inside a
# self-test that the checker believes compares two separate readings of one
# live counter, and which has been looked at and found safe.
#
# Recorded rather than suppressed, per design-decisions.md 296: the file is
# then also the list of every place in the kernel where this question has been
# asked and answered, which is the part that survives the next person.
#
# Keyed by function, never by line number: line numbers drift on every edit,
# and an allowlist that rots is a rubber stamp.
#
# An entry naming a function that no longer trips is itself reported. That
# means it was fixed (delete the line) or renamed (the entry now exempts
# something it was never meant to).
#
# Do not add a line here to buy silence for a new comparison. The four bugs
# this checker was written for -- numastat, irqstat, sysfs, irqbalance, plus
# cpu_hotplug found by the checker itself -- all looked locally reasonable too.
# If you cannot write the reason in one line, it is not safe.

kernel/src/fs/sysfs.rs::self_test  False positive, one cause, two assertions: `read_file` is a path-dispatching match whose `cpu/online` arm reads smp::cpu_count(), so the checker treats EVERY string it returns as a reading of that counter. The two flagged assertions compare a uname surface and a cache-topology `ways` value, neither of which came from that arm. Field- and path-insensitivity is the deliberate over-approximation that keeps the same function's genuine cpu/online and cpu/present checks visible -- see the checker's docstring on tail `match` handling.
