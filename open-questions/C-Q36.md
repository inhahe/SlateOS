## C-Q36 — [C] Should clicking a desktop widget open what it shows -- the calendar widget the calendar program, a photo frame its picture? — Status: OPEN (raised 2026-10-07)

**In short:** the widgets on the desktop -- a clock, a calendar, the
upcoming events, a system monitor, a photo frame, a note -- are glances:
pressing one only takes hold of it, to drag it somewhere else, and a click
that does not move it does nothing. On phones and on Windows 11 and macOS
a click on a widget opens the program behind it; on Windows 7, whose look
this desktop follows, most gadgets did nothing when clicked. The question
is which this desktop does.

**What a click would open, kind by kind:**

| Widget | Opens |
|---|---|
| calendar | the calendar program (at the day clicked, once lane E's calendar takes a date) |
| upcoming events | the calendar program at the event clicked |
| system monitor | the system monitor program |
| photo frame | the picture shown, in the image viewer |
| clock | the Date & Time settings |
| battery | the power settings |
| note | -- (it is written in where it is, as now) |

**Options.**

| | A click on a widget | *What changes:* |
|---|---|---|
| **A. A click opens it** | a press and release without moving opens what it shows; a press that moves still drags it | clicking the calendar widget opens the calendar; moving a widget is unchanged |
| **B. A double-click opens it** | as desktop icons: one click does nothing, two open | a single click is still harmless; opening takes two |
| **C. Nothing opens** (as now) | widgets are glances only; programs are opened from the start menu | nothing |

- **A**, for: what every current system does with a widget, and the
  quickest way from "I have a meeting at three" to the meeting. Against: a
  click meant to grab a widget and nudge it, released before it moved,
  opens a program.
- **B**, for: the desktop's icons work this way, so the same gesture means
  the same thing on the whole desktop. Against: few would think to
  double-click a widget, which is not an icon.
- **C**, for: nothing to learn or to open by accident. Against: the widget
  shows the event and the user must go and find it elsewhere.

**If never answered:** safe -- widgets keep doing what they do today. Only
the convenience is missing.

**Claude's recommendation:** **A**, with the press counted as a drag only
once it has moved a few pixels, so a slightly unsteady click still opens.
