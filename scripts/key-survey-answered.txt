# Keys this survey reports that have already been looked at and answered.
#
# Fields: crate<TAB>key<TAB>reason
#
# WHY THIS FILE EXISTS. The survey finds keys an app answers and never spells
# in any string of its own. Some of those are not defects, and no scanner can
# tell which: a key named by a string built at draw time, a table that spells
# a key rather than answering one, a program whose whole job is to forward
# keys somewhere else. Without somewhere to record that, every run re-offers
# the same rows and the same reading happens again -- which it has, for five
# of these crates, across three separate passes.
#
# This is NOT a suppression list. Two rules, the same two the frozen-flag
# answers file carries:
#
#   * Every line says what *makes* it not a defect -- not that it is known.
#   * A line naming a key the survey no longer reports is an error, not a
#     no-op. The tool says so and exits 1. An answer that has rotted is worse
#     than no answer, because it reads as a decision somebody made about the
#     code as it is now.
#
# A THIRD RULE THIS FILE LEARNED THE HARD WAY: answer last, not first.
# `launcher` was treated as answered for three passes on the grounds that its
# hint is built at runtime. True -- and the hint read `^1`. Caret notation in
# a desktop launcher is not a name, so the answer would have been covering a
# defect rather than recording a non-defect. It was fixed first and is
# answered now. `paint` went the same way: five of its six letters are a
# spelling table, and the sixth, `M`, was a missing row in a card that
# already existed.
#
# Run `python scripts/key-survey.py --answered` to see these with reasons.

# --- a program whose job is to forward keys, not to answer them -----------
# Every one of these is in `ctrl_key_code` or `func_key_seq`: tables that turn

# claiming "Ctrl+C -- interrupt" would be a claim this program cannot honour:
# what Ctrl+C means belongs to whatever is running inside the terminal, and in
