# Fields written in production and read only by tests -- the known ones.
#
# WHAT THIS FILE IS FOR. `check-fields-written-never-read.py` found 26 of these
# on the day it was written. A gate that reports 26 things is a gate nobody
# reads, and two of the 26 were genuine user-facing defects that would have
# been lost in the noise -- `apps/fileassoc`'s `last_export` (an Export button
# that wrote nothing anywhere) and `apps/explorer`'s `eta_secs` (a time
# remaining computed on every tick and shown to nobody). Both are fixed.
#
# The remaining 25 are listed here so the gate is green today and RED the
# moment a twenty-sixth appears. This is a triage queue, not an amnesty: every
# line is a program doing work it then throws away, and each needs looking at
# on its own terms. Some will be sound -- a field kept for a future consumer,
# or read somewhere this script's textual matching cannot see. Those should get
# a `#` note here saying so, rather than being deleted.
#
# Delete a line when the field is fixed. Do not regenerate the file wholesale:
# the notes are the point, and a regenerating flag in a sibling script silently
# destroyed hand-written prose three times before it was made to refuse.
#
# Format: <path>:<field name>, one per line. `#` starts a comment.
#
# `apps/reminders/src/main.rs:completed_at` was here and was a FALSE
# POSITIVE. It is written into the program's JSON by
# `let Self { .., completed_at, .. } = self;` -- a destructuring pattern
# reads every field it binds, and binds them by bare name, so there is no
# `.field` anywhere for a textual detector to see. Fixed, with a fixture.
#
# A line here that no longer matches anything is FATAL, not harmless: it
# would silently suppress that field if it came back. Delete it when the
# field is fixed.
#
# `apps/hearts/src/main.rs:hearts_broken` was here and was a FALSE POSITIVE.
# The detector read the `=>` of a match arm as an assignment, so
# `None if !self.hearts_broken =>` -- the rule the game is named after,
# gating whether a heart may be led -- counted as a write rather than a
# read. The field then had no production reads and was reported as
# thrown-away work when it was load-bearing logic. Fixed, with a fixture.
#
# Noticed on triage and worth a closer look first:
#   gui/desktop/src/sound_settings.rs:output_device_id -- picking an output
#     device for an app records the choice and nothing acts on it. Deferred
#     only because design-decisions 815 moves this whole panel into
#     `apps/settings`, and fixing the copy that is about to be deleted is
#     work done twice. The port must not carry it over.
#   apps/netmanager/src/main.rs:diagnostics_running -- TRIAGED 2026-09-14, and
#     it is not a drawing bug. `run_diagnostics` sets it true, builds six
#     canned results, and sets it false again before returning, so no renderer
#     can ever observe it as true. Drawing a spinner for it would be theatre.
#     The flag becomes meaningful only when the diagnostics stop being
#     simulated and acquire a real wait; until then it is dead state that a
#     future async version will want, so it is kept and annotated rather than
#     deleted.
#   gui/desktop/src/lib.rs:shortcut_message -- a message composed for the user
#     and never rendered.

# TRIAGED 2026-09-14, REAL, and the fix is a DELETION rather than a wire.
#   `Store::refresh_group_counts` walks every contact to fill
#   `group.member_count`, and it is called in production (once). Nothing
#   reads it. The number the user sees comes from `Store::group_stats`,
#   which recomputes the SAME count with the identical filter on every
#   draw -- `contacts.iter().filter(|c| c.groups.contains(&g.id)).count()`
#   appears twice, ten lines apart in behaviour.
#
#   So this is two predicates for one state, which this tree has already
#   been bitten by (see the `can_clean` comment in diskcleanup: a button
#   that looked disabled and acted enabled). Today they agree. They will
#   stop agreeing the first time someone changes what group membership
#   means and finds only one of the copies.
#
#   Fix: delete `member_count` and `refresh_group_counts`, keeping
#   `group_stats`, which is always fresh and is the one already drawn. A
#   cached count that has to be refreshed by hand is the stale half of a
#   pair waiting to happen.

# TRIAGED 2026-09-14, SOUND. Both of these are library API with no
# consumer yet, which is the island problem rather than this one.
#
#   `attempts` is parsed from `options attempts:N` in resolv.conf. This
#   crate has no retry loop and no transport -- it encodes and decodes
#   DNS messages and parses the config -- so applying the count belongs
#   to whoever sends the query. The same is true of `timeout_ms` beside
#   it. It becomes a real defect the moment a resolver here sends
#   anything and hardcodes a number instead.
#
#   `http_only` is a cookie attribute parsed from Set-Cookie and exposed
#   as a `pub` field. Parsing it and offering it IS the library's whole
#   job; enforcing it is the caller's, and there is no caller yet.
net/dns/src/lib.rs:attempts
net/httpclient/src/lib.rs:http_only
