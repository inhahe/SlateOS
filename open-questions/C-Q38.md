## C-Q38 — [C] Should other programs be able to put widgets of their own on the desktop -- and if so, should they describe them for the desktop to draw, or draw them themselves? — Status: OPEN (raised 2026-10-07)

**In short:** the desktop's widgets -- the clock, the calendar, the photo
frame, the disks, the network -- are all the desktop's own. Its list of
widget kinds has one more, "a widget from another program", which nothing
can make: there is no way yet for a program to offer one. Phones, macOS and
Windows 11 let programs add widgets (a weather app's forecast, a to-do
list's next items). The question is whether SlateOS should, and if so how
much of the widget the program controls.

**Options.**

| | A program's widget is | *What changes:* |
|---|---|---|
| **A. None** | -- | only the desktop's own kinds; "Add widget" lists nothing from programs |
| **B. Described, drawn by the desktop** | a few lines of text, a picture, a bar or a list, which the program updates when it has news | a program's widget looks like every other widget, in your theme, and cannot look like anything else -- a fake password box, say |
| **C. Drawn by the program** | a small window on the desktop that the program paints itself | anything the program can draw, as on Windows 7's gadgets; a program can make its widget look like part of the system |

- **A**, for: nothing to build or to trust. Against: the programs that would
  most want a glance on the desktop -- weather, mail, music -- cannot have one.
- **B**, for: what iOS, Android and macOS do today; the program can be asleep
  between updates, so ten widgets cost nothing; a widget follows the theme
  and the text size like the desktop's own; nothing a program sends can
  imitate the system. Against: a program is limited to the parts the desktop
  offers (text, pictures, bars, lists); something truly custom, like a
  game's live board, cannot be built.
- **C**, for: anything at all. Against: each widget is a running program; a
  widget can look like a system prompt; it draws in its own colours, not the
  theme's. Windows retired its gadgets in 2012 over the security risk of
  exactly this: each was a live program on the desktop.

**If never answered:** safe -- the desktop's own widgets work; programs just
cannot add any.

**Claude's recommendation:** **B.** It keeps every widget in the theme and
out of the system's look, and costs nothing while the program sleeps. The
programs that would use it first -- weather, the RSS reader, the music player
-- are lane E's, and each has a widget kind on the desktop waiting on a source
of its own; under B those three kinds would become what those programs
describe.

**Where it bites:** `gui/desktop/src/widgets.rs` (`WidgetKind::Custom`, and
the weather, RSS and music kinds, which draw only their names); a description
format and the channel a program sends it on (new, in `gui/`); lane E's
programs, which would send them.
