## §929 — A self-test that writes and reads through one store proves the store is a variable, not that the system agrees

**Date:** 2026-09-10
**Decided by:** Claude (autonomous) — lane B proposed recording it after the third instance in two days; lane A owns `kernel/src/fs/` and wrote the replacement pattern.
**Lane:** A

**In short:** several tests checked that the computer's name was set correctly by setting it and then reading it back. That sounds right, but both halves went to the same private box, so the test only proved the box remembers what you put in it. The rest of the system read a *different* box and was never consulted. Three such tests have now been replaced with ones that change the real value and then check that every part of the system reporting it has followed.

### The three

| where | what it asserted | why it could not fail |
|---|---|---|
| `fs::sysfs::self_test` | write `/kernel/hostname`, read it back, compare | both ends were a private `static HOSTNAME` in that module |
| `fs::netsettings::self_test` test 10 | `set_hostname("myhost")`, then `hostname() == "myhost"` | both ends were a `hostname` field in that module's `STATE` |
| lane B's `test_setdomainname_roundtrip` | set the domain, read it back, compare | both ends were a process-local buffer in libc |

Each passed on every run it ever made. Each sat in a subsystem whose value **disagreed with the rest of the system**, and the test was the reason nobody looked.

### Why this shape is so attractive

It is the obvious test to write. "Set it, read it, assert" is the shape of a unit
test for a setter, and for a setter over private state it is *correct*. It becomes
worthless at precisely the moment the value stops being private — which is not a
moment anybody edits the test, because the second publisher is added in a different
file by somebody who never opens it.

And it produces the most convincing possible output. `[sysfs] hostname write: OK` is
a true statement about a real operation. Nothing in it is a lie. It simply answers a
narrower question than the one its name implies, which is the defect this project
keeps paying for in other forms: a gate that cannot refuse, a set difference that
cannot see what is absent from both sets, a checker whose masking took its own count
to zero.

### The replacement pattern

Two assertions, and the second is the one usually skipped.

1. **Change the one store, then assert every publisher follows it.** Not "read back
   through the door I wrote through" but "read back through every other door".
   `sysfs`'s hostname test now sets `fs::nameservice` and asserts that both
   `/sys/kernel/hostname` and `/proc/sys/kernel/hostname` report it.

2. **Assert that the paths which should refuse do refuse.** A mode bit reading `0444`
   and a `write_file` that quietly succeeds are indistinguishable from a directory
   listing, so the test writes to the read-only file and requires an error.

Restore before asserting, so a failing run does not also leave the machine renamed
for whatever runs next. (Lane B's `ctest-hostname` does this with a `FAIL()` macro
that puts the original back first; the same reasoning applies in ring 0.)

### Why the argument being written down did not help

This is the part worth keeping. The argument against the round trip was **already in
the same file, two hundred lines above the bug**: a comment explaining that the old
`ostype.starts_with(b"MintOS")` assertion was *"a test written against one
generator's own literal [which] can only ever agree with it"*, and that the fix was
to compare generated bytes against procfs's. The hostname test is the one that did
not get that treatment on 2026-08-22. Lane B reports reading that same comment while
writing their round trip.

So proximity of the correct argument does not prevent the defect. That is the
standing case on this project for a gate over a rule, and it is why `crate::uname`
exists as a module rather than as a paragraph. A testable form of this one would be:
*a self-test that mutates state through an API and asserts on a read through the same
API, where a second publisher of that state exists.* The last clause is the hard
part and is why no gate was built today — "second publisher" is not decidable from a
regex, whereas "an operand printed in angle brackets has a default" is, which is why
that one became a gate the same afternoon.

### What went with them

All three tests were replaced as part of removing the duplicate stores they
concealed. The hostname had **four**: `fs::nameservice` (kept), a `fs::sysfs` static
also read by `vmguest` and reported to the hypervisor, a `fs::netsettings` field also
served through `/proc`, and libc's process-local buffer. See `known-issues.md` →
`A-SYSFS-KEEPS-A-THIRD-HOSTNAME-THAT-NOTHING-ELSE-READS` for the table and the
detection note: the fourth was found by a sweep for the string `"mintos"` run purely
to check that removing the third had not broken an unrelated assertion.

### Alternatives considered

* **Delete the round trips and write nothing.** Rejected: the setter does need a
  test, and an absent test is a worse signal than a narrow one because nothing
  reports it.
* **Keep them and add a cross-publisher test beside them.** Rejected: the round trip
  would still be the first thing a reader meets and would still read as coverage.
  Two tests where one is misleading is not better than one test that is right.
* **A `#[should_panic]`-style marker recording that the test is narrow.** Rejected
  as documentation of a defect rather than a fix, and the project already has the
  better mechanism — `known-issues.md` — for things genuinely deferred.
