## F-Q15 — Make "boots to a desktop a person can use, and a test that checks it" the next goal for every lane? — OPEN

**In short:** SlateOS boots in an emulator and passes thousands of self-tests,
but it starts no desktop: the compositor, the desktop, the login screen and
every app have never even been on its disk image (`requests/f-d-...`), and
nothing tests whether a person could sit down at it. Each of the six lanes
works down its own list, and the steps between "boots" and "usable" fall
between them. The question is whether to make that path everyone's next goal,
with a test that boots, waits for the desktop and checks the screen, so that
it stays working once it works.

**What the path is, and whose each step is:**

| Step | Lane | State on 2026-10-10 |
|---|---|---|
| The graphical programs built for SlateOS and put on the image | D | asked: `requests/f-d-the-image-carries-no-graphical-program.md`; all 148 build |
| `init` starts the compositor with its permissions | D | asked: `requests/f-bd-the-display-service-needs-two-grants-and-a-flag-from-the-session.md` |
| The compositor shows a picture and takes keys and clicks on SlateOS | F | waiting on a guest that can run it (`requests/f-a-the-guest-cannot-run-a-graphical-program-or-show-its-screen.md`) |
| The login screen, then the desktop shell, start | B, C | not started |
| A terminal and the apps open from the desktop | C, E | not started |
| An emulator window a person can use: screen, keyboard, mouse | A | asked (the same `f-a` request) |
| A test that boots to the desktop and checks it (QEMU's screen capture and simulated input) | A, with each lane's part | not started |

**Options.**

- **A. Make it the next goal for every lane** (recommended).
  *What changes:* each lane puts its step ahead of its own list until the
  test passes; you get a QEMU window with a SlateOS desktop you can use, and
  a boot test that fails when it stops working.
  For: it is the one thing every lane's work is for, and the only thing you
  can try. Against: each lane's own list waits meanwhile.
- **B. Leave each lane's order as it is; the steps get done as requests.**
  *What changes:* nothing now; the steps arrive at each lane's own pace.
  For: no lane's plan changes. Against: what got the project here -- steps
  that are no one's first job get done last.

**Recommendation:** A.

**If this is never answered:** the requests above are worked as requests,
at each lane's pace; nothing breaks, but no date can be given for a desktop
you can use.

**Where it bites:** every lane's roadmap section; `requests/` above.
